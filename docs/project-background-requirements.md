# 项目背景要求

## 文档信息

- 项目名称：My World / My Story Website（MVP）
- 文档用途：作为项目背景、产品边界、交互规则与后续开发参考依据
- 语言版本：中文

## 1. 产品定义

这是一个游戏化的个人故事网站。

访客进入网站后，不是像看普通个人主页那样顺序阅读，而是先在首页进入“我的世界”，再通过星球关卡探索不同主题，并在每个关卡里沿着“记忆时间轴”浏览网站主人的故事内容。

这个产品的目标不是做一个普通简介页，而是做一个用游戏化方式展示个人故事的互动网站。

MVP 聚焦两件事：

1. 展示体验：访客像进入游戏一样探索网站主人的个人世界
2. 编辑体验：主人可以在同一网站里编辑个人资料，并持续新增、编辑、删除关卡中的故事卡片，保存后自动发布

## 2. MVP 目标与范围

### 2.1 MVP 要达成的体验

- 访客进入后，立即感受到“这是一个可以探索的个人世界”
- 首页由固定欢迎语、个人头像入口、星球关卡导航构成核心入口
- 点击头像后可弹出个人资料浮层
- 主人默认也先看到与访客一致的浏览效果，可以欣赏自己的网站
- 主人通过 PIN 进入编辑模式后，可直接在同一网站里管理个人资料和关卡卡片
- 每个关卡中的内容以时间轴形式串联，形成“记忆档案”
- 卡片详情通过半透明涂层浮层展示，关闭后可继续浏览
- 主人可以持续往各关卡中新增内容，而不是一次性填完
- 保存 = 自动发布，不需要额外发布步骤

### 2.2 MVP 包含

- 首页固定欢迎语
- 固定 6 个关卡、固定顺序、固定星球圆环式导航
- 首页头像入口与个人资料浮层
- AI 生成 / 替换首页卡通头像
- 编辑名字、简介 / 寄语
- 在固定关卡中新增、编辑、删除卡片
- 新增卡片时，从该关卡固定 6 个主题中选择 1 个
- 卡片使用固定模板
- 卡片支持媒体内容
- 保存后自动发布

### 2.3 MVP 不包含

- 编辑首页欢迎语
- 新增 / 删除 / 重命名 / 排序关卡
- 自定义卡片主题
- 自定义模板体系
- 草稿 / 发布状态控制
- 访客评论、点赞、留言
- 完整账号注册系统
- 复杂后台 CMS

## 3. 角色、模式与整体工作方式

### 3.1 访客（Visitor）

访客可以：

- 查看首页欢迎语、头像入口、固定关卡
- 点击头像查看个人资料浮层
- 点击关卡进入内容页
- 按时间轴浏览已发布的故事卡片
- 点击卡片查看故事详情浮层
- 关闭浮层后继续浏览
- 返回首页继续探索

访客不能：

- 进入编辑模式
- 修改头像、名字、简介
- 新增、编辑、删除卡片
- 看到编辑控件
- 看到固定主题列表

### 3.2 主人（Owner）

主人是网站内容的创建者和维护者。

主人打开网站时，默认先进入浏览模式，看到的页面与访客完全一致；也就是说，主人在不进入编辑模式前，可以直接欣赏自己的网站最终效果。

主人通过输入 PIN 进入编辑模式后，可获得以下权限：

- 生成 / 替换首页 AI 卡通头像
- 编辑名字
- 编辑个人简介 / 寄语
- 新增卡片
- 编辑已有卡片
- 删除已有卡片

### 3.3 产品模式

网站只有一套前台页面，不做两套完全不同的前台 / 后台产品。

- 访客：永远停留在浏览模式
- 主人：默认也是浏览模式，但可通过 PIN 切换到编辑模式

浏览模式就是最终展示效果；编辑模式只是叠加在同一页面上的编辑能力，而不是跳转到独立后台。

## 4. 内容结构与核心规则

### 4.1 关卡、主题、卡片的关系

MVP 中共有 6 个固定关卡。每个关卡下有 6 个固定主题。

这些主题是长期复用的分类，不是固定卡槽；因此每个关卡可以无限新增卡片。主人每次新增卡片时，都必须先选择当前关卡的 1 个固定主题，但卡片创建后不可修改所属主题。

### 4.2 关卡规则

关卡数量固定、名称固定、顺序固定；关卡不可新增、删除、重命名、排序。固定主题也不直接展示在关卡页中；它们只在主人新增卡片时出现，编辑已有卡片时只作为当前卡片的所属主题信息出现。

### 4.3 卡片规则

主人可以对卡片进行新增、编辑、删除。

但不能自定义新的主题体系、模板体系，也不能控制发布与下线状态。产品规则是：保存 = 自动发布。

### 4.4 模板规则

所有主题共用同一套卡片模板；主题只负责分类，不改变表单结构。

每张卡片固定填写项为：

- 标题
- 一句话描述（网页展示不加标题）
- 有趣的细节 / 反思（网页展示标题为“背后的故事”）
- 媒体内容（图片或视频）

### 4.5 时间轴规则

关卡页中的内容以“记忆时间轴”方式浏览。

时间轴按卡片创建时间排序，不要求填写事件发生时间；展示规则为创建时间倒序，即最新创建的卡片在前。时间轴节点本身不显示明确时间；创建时间只在卡片详情浮层中显示。这里的“时间轴”是浏览结构，不是手动编排或真实事件年表。

## 5. 页面与浏览体验

### 5.1 首页

页面目标

首页是整个网站的“游戏入口”，访客进入时应立即理解：

- 这是一个个人世界网站
- 我可以通过选择关卡探索不同主题
- 点击头像可以认识这个世界的主人
- 这个网站是围绕网站主人的故事展开的

固定内容

- 固定欢迎语：“欢迎来到我的世界，请选择关卡探索我的故事”
- 该文案在 MVP 中不可编辑
- 固定 6 个关卡，名称与顺序固定
- 关卡以星球形成圆环排列，并带有类似 3D 的层次感

星球关卡导航

首页采用环形星球关卡选择器作为主要导航系统。

视觉上应具备：

- 多个星球围绕形成圆环
- 近大远小的伪 3D 层次感
- 轻微动画效果
- hover / 点击高亮效果

交互上：

- 点击某个星球，进入对应关卡页面
- 关卡页中继续浏览卡片内容
- 可返回首页继续探索其他关卡

首页头像与个人资料入口

首页展示主人的头像。这个头像既是视觉主元素，也是个人资料入口。

访客或主人点击头像后，页面弹出一个半透明涂层浮层，展示：

- 头像
- 名字
- 个人简介 / 一小段寄语

右上角有关闭按钮，点击后关闭浮层并回到首页。这个入口的作用是强化“这是我的世界”，增强主人公感，并让访客在开始探索前先认识网站主人。

### 5.2 个人资料浮层

查看态

点击首页头像后，打开个人资料查看浮层，展示：

- 头像
- 名字
- 简介 / 寄语

编辑态

在编辑模式下，点击头像仍然先打开个人资料查看浮层；但浮层内会额外显示“编辑资料”按钮。主人点击后，切换到编辑态。

可编辑内容

- AI 卡通头像
- 名字
- 个人简介 / 寄语

保存结果

保存后：

- 个人资料浮层立即更新
- 首页展示同步更新
- 自动发布

### 5.3 关卡页

进入关卡后，访客和主人在浏览模式下只会看到：

- 关卡标题
- 时间轴
- 已发布的卡片节点
- 解锁式浏览体验

时间轴节点展示

时间轴上的每个卡片节点默认显示：

- 封面图 / 视频缩略图
- 标题
- 一句话描述

时间轴节点本身不显示：

- 卡片主题
- 背后的故事
- 明确时间

解锁感

为了让关卡更像游戏探索，时间轴应加入轻量“解锁感”，例如：

- 浏览或点击节点时有高亮反馈
- 点击后返回卡片显示为点亮状态，表示已解锁
- 未浏览过的卡片保持未点亮状态
- 时间轴有“推进探索”的感觉

这里的解锁感只作为视觉和交互体验存在，不引入复杂游戏规则，也不记录真实已读 / 未读状态。

### 5.4 卡片详情浮层

访客点击某个时间轴卡片后，不跳到新页面，而是弹出一个半透明涂层浮层展示详细内容。

浮层中展示：

- 标题
- 图片或视频
- 一句话描述（网页不展示字段标题）
- 有趣的细节 / 反思（网页标题展示为“背后的故事”）
- 主题
- 创建时间

右上角有关闭按钮；关闭后回到时间轴，继续浏览其他卡片。

## 6. 编辑体验与交互流程

### 6.1 进入编辑模式

主人进入网站后默认是浏览模式。

网站右上角放一个低调但清晰的编辑入口，例如小齿轮图标。点击后弹出 PIN 输入框：

- 标题：进入编辑模式
- 输入框：4-6 位 PIN
- 按钮：取消 / 确认

PIN 正确后：

- 关闭弹窗
- 页面顶部出现轻量状态条
- 页面主体不变，但出现编辑控件

主人点击“退出编辑模式”后：

- 页面恢复为浏览模式
- 所有编辑按钮消失

刷新页面后，也会自动退出编辑模式；如需继续编辑，必须重新输入 PIN。

### 6.2 编辑个人资料与头像

头像生成规则

主人第一次设置头像时：

1. 输入头像要求
2. AI 自动生成 3 张候选头像
3. 3 张候选同时展示
4. 主人单选 1 张作为首页头像并保存

头像更换规则

后续如需修改头像：

1. 点击重新生成 / 更换头像
2. 修改或补充头像要求
3. AI 再生成 3 张候选
4. 同时展示 3 张候选
5. 选择其中 1 张替换当前头像

头像输入方式

头像生成采用固定字段 + 补充说明的输入方式，字段包括：

- 发型
- 表情
- 艺术风格
- 配色方案
- 服装样式
- 补充说明

编辑态中的头像入口

在个人资料编辑态里，头像区域直接显示“更换头像”按钮。

头像功能边界

MVP 只支持：

- 输入头像要求
- 生成 3 张候选
- 选择 1 张使用
- 编辑名字
- 编辑简介 / 寄语
- 重新生成替换头像

MVP 暂不支持：

- 高级精修
- 局部修改
- 手动画布编辑
- 多头像收藏管理

### 6.3 新增卡片

新增入口

新增卡片入口采用时间轴内嵌式入口，而不是页面角落固定按钮。

- 空状态时：在时间轴主区域显著显示一个大号虚线插槽卡片，文案为“添加第一张故事卡片”
- 已有内容时：仅在编辑模式下显示在时间轴末端，采用大号虚线插槽卡片，文案为“新增故事卡片”
- 浏览模式 / 访客视角：不显示新增入口

新增流程

1. 进入某个关卡
2. 点击时间轴末端的“新增故事卡片”入口
3. 打开一个居中半透明大浮层弹窗
4. 在同一个浮层里完成以下内容：
   - 选择卡片主题
   - 填写标题
   - 填写一句话描述
   - 填写有趣的细节 / 反思
   - 选择主媒体类型
   - 上传或插入媒体内容
5. 点击保存
6. 卡片创建成功
7. 自动归入当前关卡与所选主题
8. 自动发布
9. 新卡片按系统排序自动进入时间轴
10. 主人立刻看到最终展示效果

新增规则

- 新增 / 编辑采用一步完成交互，不拆成两步
- 主人不能选择插入位置
- 时间轴末端的新增插槽只是操作入口，不代表内容会加在末端
- 新卡片保存后会按创建时间倒序自动排到时间轴前面

### 6.4 编辑与删除卡片

编辑入口

在编辑模式下，主人点击时间轴上某张卡片，卡片右上角显示编辑 / 删除入口。

编辑流程

1. 进入某个关卡的编辑模式
2. 点击某张卡片
3. 看到卡片右上角的“编辑 / 删除”操作按钮
4. 点击“编辑”后，打开居中半透明大浮层表单，并预填已有内容
5. 修改标题 / 一句话描述 / 有趣的细节 / 反思 / 主媒体内容
6. 点击保存
7. 卡片实时更新并自动发布

编辑卡片时，不可修改所属主题。

删除流程

1. 主人点击某张卡片
2. 点击卡片右上角的“删除”按钮
3. 弹出确认框
4. 确认后，该卡片从对应关卡的时间轴中移除
5. 浏览模式中也不再显示

删除不会影响后续继续从同一主题新增别的卡片。

编辑表单形式

新增 / 编辑卡片统一使用居中式半透明大浮层弹窗：

- 内容区允许纵向滚动
- 底部固定操作区：取消 / 保存
- 若关闭时内容已改动，需要二次确认

## 7. 卡片媒体规则

### 7.1 媒体目标

媒体内容的设计必须帮助主人快速、低门槛地添加内容，并让前台展示保持美观统一。因此 MVP 只支持最适合视觉展示的两类媒体：图片和视频。

### 7.2 必填与主媒体类型

每张卡片的媒体内容为必填项。

每张卡片只支持 1 个主媒体类型，也就是只能二选一：

- 图片
- 视频

不支持纯文字卡片。

### 7.3 图片规则

图片支持：

- 从设备选择图片
- 拍照上传
- 粘贴图片

体验目标：

- 上传快
- 可预览
- 可删除重传
- 最多 3 张图片

### 7.4 视频规则

视频支持：

- 上传短视频
- 粘贴外部视频链接

体验目标：

- 能快速插入已有视频内容
- 可预览
- 可删除重传
- 不做复杂视频管理
- 最多 1 个视频

### 7.5 视频链接规则

- 前台采用直接嵌入播放
- 外部视频链接支持任意可嵌入的视频链接
- 只有系统可成功识别、且可被嵌入播放的链接，才允许保存和展示

## 8. 空状态

即使主人还没有添加任何内容，网站也应该是可浏览的。

### 8.1 首页空状态

首页永远有：

- 欢迎语
- 默认头像占位 / 已生成头像
- 固定关卡导航

### 8.2 个人资料空状态

如果主人还没填写名字和简介：

- 头像浮层中显示默认占位文案
- 编辑模式下可提示“编辑个人资料”

### 8.3 关卡空状态

如果某关卡还没有添加故事卡片：

- 访客看到：该关卡还没有故事内容
- 主人在浏览模式看到：与访客一致
- 主人在编辑模式看到：空状态提示 + 新增第一张故事卡片入口

## 10. 设计原则

本 MVP 应遵循以下原则：

1. 一个网站，不做两套前台
2. 主人默认先看浏览模式
3. 编辑模式是叠加能力，不是独立后台
4. 固定关卡、固定主题、固定模板
5. 主题是分类，不是卡槽
6. 固定主题不在关卡页直接展示
7. 卡片以时间轴形式展示
8. 保存即发布
9. 媒体添加必须低门槛且美观
10. 时间轴是浏览结构，不是手动编排结构
11. 沉浸感优先于后台感

## 11. MVP 成功标准

### 对访客

- 一进入首页就能理解“这是一个可探索的个人世界”
- 点击头像能快速认识网站主人
- 能清楚地点击关卡并沿时间轴浏览内容
- 点击卡片后能通过浮层查看详情并继续探索
- 整体体验有游戏感、探索感、个人化

### 对主人

- 能直接看到与访客一致的网站效果
- 能顺利通过 PIN 进入编辑模式
- 能轻松生成并替换头像
- 能编辑名字与简介 / 寄语
- 能在固定关卡中快速新增、编辑、删除卡片
- 能理解每个关卡固定 6 个主题的分类方式
- 能随着时间不断添加内容，而不会被系统限制
- 能用简单模板完成内容输入并自动发布

### 对产品本身

- 页面逻辑清晰
- 权限逻辑简单
- 不依赖复杂后台
- 具备持续积累个人内容的能力
- 视觉与交互统一
- 为后续扩展 AI 功能预留空间
